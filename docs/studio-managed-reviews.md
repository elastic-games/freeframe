This integration keeps the original FreeFrame dashboard, project pages, asset review UI, and provider asset/version/comment IDs. In managed mode, the embedded child sends finite JSON/SSE envelopes through postMessage to the exact mounted, signed-in Studio parent. Both directions check the exact origin and source Window. The parent fetches only the fixed same-origin Studio `freeframe-transport` route with same-origin credentials. Cookies, credentials, tokens, caller headers and arbitrary URLs never cross the frame boundary. Studio checks the signed-in actor/owner, organization, and active canonical FreeFrame binding on every operation, then signs a one-use native delegation for the exact provider method, path, query, and body. The FreeFrame API checks its own membership and object graph again. The browser never receives a FreeFrame bearer or delegation token.

## Scope and limits

Managed transport allows project-scoped asset/version/comment/folder reads and edits, exact member read, and multipart upload initiation/completion. It returns the canonical Studio project name in provider project responses. Inside Studio, the managed FreeFrame dashboard lists only active canonical bindings the owner can access. Project create, rename, archive, invite/share, instance settings, notifications, and broad user search are unavailable in managed mode until canonical lifecycle and revocation contracts are complete. Managed requests never fall back to a direct legacy provider session. An unrecognized route receives a denial from the Studio transport policy.

In the current managed standalone entry, review reads do not mount until the user opens Studio. Open in Studio retains only the exact supported project/asset route and folder/version/comment/compare context, dropping credentials and redirect parameters. The dashboard's canonical list is reached inside Studio. Existing unmanaged standalone behavior remains separate.

The managed upload panel shows only the project in the current page URL. It does not fetch the old account-wide `/me/assets` upload history, and it stores resumable rows under a separate browser key from legacy FreeFrame sessions. Clearing completed managed rows affects only the current project. A denied asset or comment read clears the previous review and shows an explicit Retry action; Retry checks the current Studio grant again. Project, asset, folder/tree and trash read failures also show localized Retry instead of an empty-success list.

Each new BFF request checks the current binding. An already-issued S3 object, HLS, or upload capability can remain usable for up to 300 seconds after revocation; already delivered bytes cannot be recalled. The BFF SSE stream is capped at 55 seconds and rechecks access on reconnect. Existing unmanaged public/share links are a separate provider authorization surface and are not revoked by Studio project removal. Review those links before treating canonical removal as a complete media recall. The historical source assessment reported no provider snapshot/hash `/studio/review-read` endpoint and therefore no imported review snapshot verification in that baseline; it is not a current endpoint assessment for this frontend repair. Exact version and comment lineage remain authorized by the existing provider policies.

The parent relays actual ordered SSE bytes with bounded ACK backpressure. Per-document handshakes, replay/size/concurrency/time bounds and abort/unmount/reload/pagehide/bfcache cleanup prevent stale requests. Authorization failures stop reconnecting until scope changes. Media bytes still use existing provider/storage capabilities, not postMessage.
